# External Pattern Synthesis

Read this file when updating `manuscript-workflow`, when the user asks how it differs from other writing skills, or when a manuscript task explicitly asks to learn from an exemplar paper or public skill.

This file records high-level workflow patterns. It is not a copy, paraphrase bank, or vendored subset of upstream repositories.

## Patterns Rebuilt Locally

| External pattern observed | Local manuscript-workflow equivalent |
|---|---|
| Motivation-first paper construction | `Motivation Thread`: one controlling reason for the paper before drafting |
| Source-aware intake | `Material Passport`: classify local results, external evidence, style exemplars, stale materials, and gaps |
| Learn from exemplar papers | `External Pattern Learning`: capture section jobs, result order, figure logic, paragraph rhythm, and audit gates |
| Staged academic writing | `Routing` plus `Workflow`: build, rewrite, section draft, review, and final package paths |
| Claim verification | `Evidence Map` and `Claim Register`: each claim gets a source, evidence level, and allowed wording |
| Anti-leakage and material grounding | Facts must come from user materials or cited sources, while exemplars teach style only |
| Reviewer-style critique | `Review Gate`: method, domain, argument, and skeptical review passes |
| Reset or checkpoint boundary | Project profile plus material passport, so future sessions can restart from explicit assumptions |
| Final artifact packaging | LaTeX/PDF path reporting, audit artifact, and unresolved-gap reporting |

## What This Skill Must Not Do

- Do not copy upstream SKILL.md wording, prompts, templates, examples, or directory layouts into this repository.
- Do not use a reference paper or skill as factual evidence for the user's local results.
- Do not blur "style exemplar" with "scientific support".
- Do not turn one project's restrictions into generic workflow rules.
- Do not overwrite user drafts or published artifacts unless explicitly requested.

## How To Learn From A New Reference

When the user gives a paper, journal instruction, previous manuscript, or another skill:

1. Identify its writing job: motivation framing, section order, result narration, reviewer checklist, package format, or citation style.
2. Extract reusable decisions as short labels, not reusable sentences.
3. Translate those decisions into the current project's vocabulary.
4. Record any hard constraints in the project profile, not in the generic skill.
5. Run the claim register before drafting prose.

## Clean Adaptation Rule

For every borrowed idea, make it pass this test:

- Can it be described as a general process step rather than a line of text?
- Does it still work for a different field, dataset, or journal?
- Is the factual content supplied by the user's current materials?
- Is the output visibly shaped by the user's project rather than the upstream repository?

If any answer is no, rewrite the step or leave it out.
